# Feature: simulation (simulator + case-editor + shared/ventilator-console)

## Objective
Migrate the simulation features onto the template base:
- `simulator` (all roles): catalog, running console, result, replay and the exam practical slot;
- `case-editor` (teacher/admin): list and sectioned editor.

Both are built on a generic `src/shared/ventilator-console`. The engine runs in a Web Worker. Audit: `odd/simulation-audit.md`.

## Why
The legacy `/simulador` streams backend Socket.io data and has no confirmation pattern, alarms, modes beyond VCV/PCV, replay or exam integration. The backend already exposes the engine-based session and clinical-case API.

## Decisions (orchestrator, 2026-10-15; the author asked to run every phase without stopping or asking)
1. **Folder structure**: `src/features/<name>/{api,application,UI,index.ts}`, with static config in `application/config`, because the ESLint boundaries only accept these layers. This is the same decision as ai-chat.
2. **Engine vendoring**: `scripts/sync-sim-engine.mjs` copies `ventylab-server/src/features/simulation/domain/engine/**` and `common/domain/ventilator/ventilator-limits.ts` into `src/shared/sim-engine/` (generated header + `--check` mode). This is the same model as `scripts/generate-api.mjs`, and `next.config` is not touched.
   - The ventilator limits copied from the backend are the single source for the control limits.
3. **Worker**: `src/shared/sim-engine/runtime/` holds a pure stepping loop (fixed step, wall clock × multiplier, catch-up after a background tab, batches) and a thin `sim.worker.ts` (`new Worker(new URL(...), import.meta.url)`). The loop is unit-tested directly because jsdom has no Worker.
   - The backlog has no cap, by design: no simulated time is lost or invented. The loop steps only while running; a backlog owed before a pause is kept and caught up after resume. A long hidden tab therefore fast-forwards on return, in chunks of at most 2000 simulated ms per tick (`maxCatchUpMsPerTick`).
4. **Waveform renderer**: a raw canvas sweep/scroll renderer with freeze and a measurement cursor is added to `shared/waveforms`. Chart.js would cost an estimated 5–10 ms per frame at 50 Hz for three curves. `WaveformChart` (Chart.js) stays for static charts.
5. **Pause maneuvers**: the engine has none (only the `inspiratoryPauseS` setting), so no hold buttons are shown. Reported.
6. **Patient monitor**: shows only what the engine outputs (SpO2, PaO2, PaCO2, pH, MAP). HR, systolic/diastolic BP, temperature and Glasgow are dropped.
7. **Alarm priority**: the engine has no priority. A static map from alarm type to high/medium/low lives in the console config, and the backend gap is reported.
8. **Engine version**: there is no endpoint. The vendored `ENGINE_VERSION` is compared with `engineVersion` returned by `POST /simulation/sessions` (and by the replay endpoint). FREE shows a warning; EXAM blocks the console before the worker starts.
9. **Time multipliers**: there is no endpoint. The allowed values are read from the generated OpenAPI type (`1|2|4`), not hardcoded in the UI.
10. **Rubric editor**: `src/shared/rubric-editor` receives BOTH editors:
    - the promoted parameter rubric editor, which evaluation-authoring re-imports with no behaviour change;
    - a new outcome rubric editor (TARGETS_REACHED, TIME_IN_RANGE, … + assistance policy + passing score), because a case `defaultRubric` uses the outcome schema.
11. **Legacy `/simulador`**: it is the only UI for the physical ventilator (reservations, connection, MQTT). It is NOT redirected until ventilator-lab is migrated, because that would destroy a working capability. Nav keeps it as "Ventilador real", and the new "Simulador" entry points to `/simulator`. Any other legacy simulator route redirects.
12. **Dropped legacy extras (YAGNI)**: draggable metric-card layout, TXT export, PCV auto-adjust. They are listed in the parity checklist.
13. **Git**: the same as previous migrations. Conventional Commits on `master`, no AI attribution, no branches. Each commit is reviewed (consent granted by the standing instruction), with an independent reviewer when native review fails with `lens_context_budget_exceeded`. Push once at the end.
14. **Protected-zone exception (tooling only)**: path additions in the `package.json` lint script, `tsconfig.strict.json`, `eslint.config.mjs` and `vitest.config.ts`, the same as previous migrations.
15. **E2E / profiling / visual**: Playwright is not installed, and there is no browser or servers. These checks are documented as manual and pending; unit tests cover the logic.
16. **Console normal ranges (deliberate exception)**: the default normal ranges in `console.config.ts` are front-end teaching defaults (adult lung-protective), not backend data. Adapters override them through `adapter.ranges` (metrics + patient; it wins per key), consumers through the `metricRanges` / `patientRanges` props, and `null` disables the highlight for a value.

## Backend gaps to report
- **TOP GAP: the server time is unreadable cross-origin.** The EXAM wall-clock resume reads the HTTP `Date` header of `GET /simulation/sessions/{id}/state`, but the backend CORS config (`CORS_EXPOSED_HEADERS`: Content-Disposition, Retry-After, X-Export-Truncated, …) does not expose `Date`, so a browser on another origin never sees it. Exact remedy (backend, not done from the front): add `Date` to `CORS_EXPOSED_HEADERS` in `ventylab-server/src/common/infrastructure/config/cors-origins.ts`, OR add a `serverNow` field to `SimulationSessionStateDTO` (as the attempt DTOs have). The msw/jsdom tests do not enforce CORS exposure, so they pass either way. Front mitigation (review of 180a0a1): when `/state` has no readable clock, an EXAM resume whose record knows the attempt reads the server time from the `GET /evaluation-attempts/{id}` BODY field `serverNow` (the same source T9 uses for the clock offset; body fields are readable cross-origin); a lost record (another device) or a failed read degrades to backlog 0 (resume at the last known time). No session endpoint carries a server timestamp in its body.
- No endpoints for engine version, ventilator ranges, physiological ranges or time multipliers.
- No pause maneuvers in the engine, and no alarm priority.
- The case list has no status or validated flags (only `/definition` has them). `/definition` requires `clinical-cases:manage` (TEACHER+), so a student can never see the validated flag: the catalog badge stays hidden until the list summary carries it (T5).
- The session history (`SimulationSessionDTO`) carries only `caseId`, no case title: the front resolves titles with one `GET /api/clinical-cases?ids=…` per page, and a case that is no longer published shows "Caso no disponible" (T5).
- The list summary has no short `summary` field: the card shows `description` (T5).
- There is no test-run for an unsaved draft and no revert of expert validation.
- Teacher replay access is enforced only by the backend, and is unverified from the spec.
- Neither `/replay` nor `/state` (nor the start response) carries the session `mode`; after a lost session store the console infers EXAM from a non-null `expiresAt` (T6).
- The session `timeMultiplier` is fixed at start and the backend bounds every event `simTimeMs` by `wall elapsed × timeMultiplier + tolerance`, so the client playback multiplier can never exceed the session multiplier; since the T5 fix the catalog card picks the session multiplier (×1/×2/×4, default ×1) at start, and the console FREE selector offers only values ≤ it (T6).
- The generated OpenAPI type of `SimulationEventInputDTO.payload` is an empty object (`Record<string, never>`); the front casts the documented `{changes}` payload (T6).
- The engine alarm thresholds have no bounds in the contract or the engine, so the read-only "Límites de alarma" panel of the console is not fed (it needs min/max/step); thresholds are fixed per case (T6).
- The backend maximum event batch size (`SIMULATION_MAX_EVENT_BATCH_SIZE`) is not exposed; the client caps batches at 50 (T6).
- No session endpoint carries the accumulated pause time of a FREE session, so the wall-clock resume after a reload cannot subtract it (T6-fix).
- A student cannot read the assistance policy of a session: the case `defaultRubric` is only in `GET /clinical-cases/{id}/definition` (`clinical-cases:manage`, TEACHER+) and the EXAM question `rubric` (`StudentQuestionDTO`) only after the grade is published; no session DTO carries it. The console fails safe (FREE enabled; EXAM disabled with "No se pudo verificar la política de asesoría") and accepts the policy from the host (`assistancePolicy` prop, for T9) (T7).
- The rubric has no penalty amount (`ClinicalCaseRubricDTO` has only `assistancePolicy`), so the confirmation states that each request is penalized but not by how much (T7).
- The session summary has no dedicated time-to-stabilise or safety-violation fields: the result page reads them from the `TIME_TO_STABILIZE` / `SAFETY_VIOLATIONS` breakdown criteria, so they appear only when the session rubric includes those criteria; the breakdown `justification` texts come from the server in English (T8).
- `GET /replay` carries no session length: the replay page uses the `GET /state` simulated time (fallback: the last recorded event) (T8).
- The session data (`SimulationSessionDTO`) carries `attemptId` but not the `evaluationId` the attempt route needs: "Volver al examen" uses the exam return record the exam flow writes (`examReturnStore`, T9), otherwise the evaluations list. The mode comes from the history `ids` filter, which lists own sessions only, so a teacher reading a student's session sees no rubric breakdown (T8).
- The replay data has no alarm timeline: the replay time bar marks the recorded events (PARAM_CHANGE, AI_HELP, ALARM_ACK, CASE_EVENT) plus the alarm onsets of a second local replay run in the worker (T8).
- The EXAM question carries only `clinicalCaseId` and, after publication, the opaque `rubric`: before the grade is published the slot cannot show the rubric rules or the assistance policy (the console stays fail safe: assist disabled). Neither the question nor the rubric fixes a time multiplier, so an exam session uses the contract default ×1 (`EXAM_TIME_MULTIPLIER`). `StartSimulationSessionDTO.caseId` is ignored in EXAM (the server uses the question case). The attempt route has no question parameter: the return lands on the attempt URL and the player restores the last question index it stored (the SIMULATION one) (T9).
- The exam context (attempt, question, return URL, policy, clock offset) lives only in this tab's session record; no session DTO carries the evaluation id or the policy. On another device the console returns through the exam return record or the evaluations list, and the assist stays disabled (T9).
- The event time tolerance (`eventTimeToleranceMs`) and the time-ahead error code are not in the contract (the 403 description only says "simulated time ahead of real time"); the client keeps a conservative 2 s × multiplier margin and treats any 403 other than `simulation.session_access_denied` as time ahead (T6-fix 2).
